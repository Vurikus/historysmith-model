# Генерация мира

Корневой элемент — объект с массивом `raws`. Каждая запись содержит поля `modelName` и `frequency`, где `modelName`
ссылается на известный товар из `model/craft/product.json`, а `frequency` — число в диапазоне [0, 1]. Неизвестные имена
товаров и повторные записи запрещены. Товар можно не указывать: это равнозначно нулевой частоте, он не участвует в
распределении.

Частота задаёт целевую долю всех тайлов мира, содержащих продукт: 0 отключает размещение, 1 задаёт размещение на каждом
тайле. При размещении целевое количество тайлов округляется; фактическое размещение ограничено доступными местами
обитания с подходящими климатом и типом местности, а также вместимостью тайла для каждой категории. Частоты независимы и
не нормализуются до суммы 1. Для произведённых товаров и домашнего скота частота равна 0. Каждое размещённое
месторождение изначально содержит 1000 единиц ресурса (значение задаётся в игровых константах сервера).

## Преобразования свойств в товары

`product-conversions.json` содержит объект с массивом `conversions`. Каждая запись задаёт:

- `property` — имя свойства из `model/craft/property.json`;
- `product` — имя выходного товара, который должен входить в каталог товаров этой партии;
- `volume` — фиксированный положительный целый объём выхода. Используются единицы `WorldProductMatrix`: 100
  соответствует одной игровой единице выхода на одну игровую единицу свойства.

Менеджер матрицы обходит все категории товаров партии с `isExtraction = true` и заполняет преобразования для всех
разрешённых свойств этих категорий. Для общего свойства нескольких категорий создаётся одна запись матрицы. Пропуск
свойства запрещён: неполная матрица отклоняется при создании.

Для одного свойства задаётся ровно один выходной товар. Объём из файла переносится в матрицу без изменений: диапазонов и
случайного выбора нет. Повтор свойства, неизвестное свойство, недоступный в партии товар и неположительный или нецелый
объём считаются ошибками.

Сейчас `isExtraction` включён у диких животных, скота, минералов, деревьев, трав и рыбы. Вода обрабатывается отдельной
подсистемой водоснабжения. Готовые товары, материалы и изделия не являются источниками матричной добычи.

## Конструктор названий клеток

`tile-names.json` описывает ключевые имена клеток. Ключевое имя — не готовое название: клиент заменяет в нём каждый ключ в
двойных фигурных скобках названием из своих переводов (`assets/text/main.csv`), а весь остальной текст оставляет как есть.

- `default` — универсальные имена, которые подходят любой клетке. В конструкторе они не участвуют, но ключи в двойных
  фигурных скобках в них тоже заменяются при показе.
- Остальные поля называются по `modelName` рельефа из `model/tile/relief.json`. Значение поля — объект с двумя массивами:
  - `patterns` — шаблоны имени, где `{{%}}` отмечает ровно одно место подстановки;
  - `values` — подставляемые названия элементов рельефа.

Шаблон `{{%}} caucasus` и значение `gorge` дают ключевое имя `{{gorge}} caucasus`, а клиент показывает его как
`Ущелье caucasus`. Ключ `gorge` клиент ищет в переводах как `TXT_TILE_NAME_GORGE`: пробелы заменяются на `_`, буквы
становятся заглавными. Если перевода нет, вместо ключа показывается сам ключ без скобок: `gorge caucasus`.

Имя выбирается по преобладающему рельефу клетки; если преобладающего нет, берётся рельеф любой из микроклеток. Генератор
старается не повторять имена, но повторы допустимы. Водные клетки вдали от берега получают общее имя с соседними.
